# 点云策略部署定位偏差：归因阶梯与抗遮挡实验方案

> 适用版本：stage 2/3/4 点云策略（`configs/xarm7_pick_pointcloud_env_cfg.py`）
> 目标：定位真机部署「定位不准」的系统性偏差来源（模型 vs 感知；感知内哪类），
> 并据此确定对症的算法改进方向，最终提高部署泛化能力。
> 关键结论（前期分析 + 实机观察）：
> 1. 相机参数与训练解耦——重标定只需改配置常量、无需重训（前提：标定偏差在 1cm
>    噪声预算内、相机视角无明显变化）。
> 2. 遮挡分两类：**第一类 = 漏检**（工件一部分不在掩码里 → 点云缺一块）；
>    **第二类 = 误检**（背景/桌面像素进掩码 → 点云多一圈假点）。
> 3. 遮挡机制作用在**基座系几何**上（`occlusion.py` 的 halfspace/sphere 等），与
>    掩码来源（GT / YOLO）正交——两类遮挡可分开量化，遮挡可与 YOLO 掩码叠加。
> 4. **夹爪自遮挡已在仿真中自动建模**：`instance_id_segmentation_fast` 逐像素 +
>    渲染器 z-buffer（[xarm7_pick_pointcloud_env_cfg.py:754-758]），被夹爪挡住的
>    像素天然不含在工件掩码里，与真机 YOLO-seg 行为一致。因此 `occlusion.py` 的
>    几何遮挡建模的是**外部随机遮挡**，不是自遮挡。

---

## 1. 背景与问题定义

**现象**：stage 2（GT 实例分割）训练的遮挡策略在真机部署（YOLO 掩码）上出现系统性
定位偏差。

**早期 stage2 策略部署的初步观察**（stage2 策略 + YOLO 观测 = 分布外 + 掩码源错配，
信息贫，**不作锚点**，仅作提示）：

- 中间位置、稍微有倾角的工件表现最好，几乎无偏差；
- 远处不准、横放更差斜放更好（中近处规律）。

> 这些观察出自「在 GT 掩码上训练的策略 + YOLO 掩码观测」，分不清是「策略的分布外
> 脆性」还是「环境的真实误差」，不能指导整个方案。它唯一已经生效的结论是「必须训
> stage4」——这已进入第 0 步。真正的锚点是第 1 步 stage4 部署得到的新签名。

**要回答的三个问题（按顺序）**：

1. 偏差来自**模型/表征本身**，还是**感知链路**？
2. 若来自感知，是**哪一类**（缺 vs 多），还是掩码源（YOLO）？
3. 剩下的仿真↔真机 gap（外参/深度/轨迹）有多大？

只有定位完成，才谈得上对症改进：盲目「加一个扰动让 RL 自己探索」没有意义；
定位之后的「对症扰动 + RL 训练」才是可行的。

---

## 2. 三现象三分法（先分清是三个不同的东西）

实机的三个现象不是一回事，别混在一起：

| 现象 | 本质 | 归类 | 杠杆 |
|---|---|---|---|
| 远处不准 | YOLO 距离分割退化 | 掩码源（第二/三类），距离相关 | stage4 训练吃掉 |
| 夹爪接近遮挡 | 机械臂自遮挡 | 第一类，确定性、随接近增大，**仿真已自带** | 仿真↔真机对齐（L4/L5），不是加机制 |
| 外部遮挡 | 第三方物体挡住 | 第一类，随机 | `occlusion.py` 几何遮挡建模 |

关键：**夹爪自遮挡不是独立误差源**，它是「相机外参 + 接近轨迹 + 夹爪几何」的下游
结果。所以它没法被当成「仿真和真机天然共享」的因素干净地排除——只要外参/轨迹没
对齐，仿真的自遮挡就可能和真机不同。判断它是否对齐，靠的是第 1 步的忠实度对照和
第 5 步的 `visible_ratio` 对照，而不是「加一个遮挡机制」。

## 3. 总体思路：两条链 + 一个无条件基线

```
链 B 基底（无条件先做）：stage4 baseline（YOLO 掩码）
    —— 既是部署权重，也是后面一切仿真↔真机对照的仪器

链 A（定位链，干净因子，一次只变一个因素）
  stage 2 GT 掩码 ── +遮挡探针 C（纯第一类：缺）
                   ── +膨胀探针 D（纯第二类：多）
                   ── stage 4 YOLO 掩码（掩码源 gap）
        ↓
  产出：一个「决策」——哪类绑定？要不要为它训练？RL 能不能吸收？

链 B（部署链，现实分布，一次包含全部现实因素）
  stage 4 YOLO 掩码 ── + 绑定的那类扰动（叠加，不是替换）
        ↓
  部署训练 → 真机验证
```

**两条链之间只传递决策，不传递「等效的观测条件」、也不传递权重。**

- 链 A 是干净因子仪器：GT 掩码没有假阳性也没有漏检，所以「GT + 遮挡」是纯第一类、
  「GT + 膨胀」是纯第二类，互不污染——这是定位准确性的来源。
- 链 B 的观测分布 = 真机分布（YOLO 掩码噪声 + 物理遮挡同时存在），训练分布与部署
  分布一致，不存在「从 stage2+occ 迁移到 stage3」的迁移假设。
- **stage4 是两链的公共基底**：真机用 YOLO，最终权重非 stage4 不可；且仿真↔真机
  对照必须掩码对齐（两边都用 YOLO），否则 gap 被掩码源污染、无法解释。所以 stage4
  基线**无条件先训**，不取决于任何定位结论。

## 4. 前置：口径、协议与待开发工具

### 4.1 评估口径（沿用 `scripts/train/eval_reach_compare.py`）

- 碰撞即终止（collision + time_out 终止保留，reach_success 关闭）。
- 成功 = episode 结束前**曾进入过**阈值，三档：`1cm/3°`、`0.5cm/3°`、`纯位置 1cm`。
- 碰撞独立统计。
- 主要看 `1cm/3°` 档成功率与「最终抓取目标点误差」（grasp-target error）。

### 4.2 固定评估协议（所有阶梯级共用）

- 同一批工件位姿（固定 `--seed`）、同一 episode 数（建议 ≥500）、同一指标。
- 每一级对比**只变一个因素**，其余（位姿、指标、episode 数）全部固定。
- 两种评估口径**不可混用**，每次对比只选一个：
  - **冻结策略 + 换观测源**：同一 checkpoint，只换喂给它的点云来源 →
    回答「该感知扰动对已有策略的伤害」。（定位的主口径）
  - **各自训练、各自评估**：该观测条件下训练出的策略评自己 →
    回答「该观测条件下模型能学到什么水平」（可达上限/可行性）。

### 4.3 待开发工具（3 个小工具，改动均在现有 idiom 之内）

| 编号 | 工具 | 用途 | 改动量 |
|---|---|---|---|
| T1 | pointcloud 版 eval worker | 观测源可参数化的评估入口：`--obs gt \| gt_occ \| gt_dilate \| yolo`，照 `eval_reach_single.py` 骨架 + 观测源开关实现 | 小 |
| T2 | GT 掩码像素膨胀 `--edge_dilate_px` | 第二类探针：bool 掩码 `(B,H,W)` 上 `F.max_pool2d(mask.float(), k, 1, k//2) > 0` 即 binary dilation，在掩码生成后、`mask_depth_to_pointcloud` 前插一行 | 一行 |
| T3 | YOLO + 遮挡观测函数 | 把 `point_bridge_point_cloud_occluded` 的掩码块换成 `yolo_masks(...)`（照 `point_bridge_point_cloud_yolo` 那 3 行），其余逐字不动；配套 setter | 小（复制+换掩码块） |

**当量标定工具（已有，直接用）**：

- 第二类当量：`tools/eval_yolo_weights.py`——在仿真渲染图上跑 YOLO 与 GT 掩码对比，
  量出真实 YOLO 掩码相对 GT 的**边界膨胀宽度**（p50 / p95，像素）。
- 第一类当量：从真机部署录像（`logs/deploy_pointcloud/video_*.mp4`，纯 RGB 可直接
  回灌）量「夹爪压住工件时可见面比例」。
- 真机点云采集：`scripts/camera/real_roi_pointcloud.py --save_points`。

## 5. 定位阶梯（stage4 为第 0 步）

### 第 0 步（无条件）训练 stage4 baseline

- **理由**：真机用 YOLO，最终权重非 stage4 不可；且后面一切仿真↔真机对照都必须
  掩码对齐（YOLO 侧）。这不是盲训、不是扰动实验，是部署基线的必然。
- **顺带产出**：stage2 vs stage4 的仿真内对比 = **掩码源效应**（第二/三类 + 距离
  效应），一次对照就拿到，不用真机。
- **快捷预览（可选）**：不等 stage4 训练完，用 stage2 冻结策略 + 换 YOLO 观测源，
  先看掩码源第一眼。但这是预览，最终以 stage4 训练结果为准。

### 第 1 步（分水岭）真机部署 stage4 → 仿真忠实度对照

- **先取干净锚点**：把 stage4 baseline 部署到真机（`deploy_pointcloud_policy_xarm7.py`），
  按「横放/斜放 × 近/中/远」扫位姿，记录它的效果与趋势（**新签名**）。这时的签名
  不再受掩码源错配污染——stage4 策略在 YOLO 上训练、在 YOLO 上部署，是分布内的。
- **再对照**：用同一个 stage4 baseline 在仿真里扫同样的位姿网格，看是否复现真机
  新签名。这是整个方案的**分水岭**。
- **判据**：
  - **复现** → 仿真可信，问题在**仿真内**，走第 2–4 步；
  - **不复现** → 仿真和真机脱节，问题在**仿真↔真机之间**，**别训练**，直接跳第 5 步。

### 第 2 步（仿真内分支）能力门槛 stage1

- **操作**：训练 stage 1（绕过相机、GT 全表面采点、无遮挡无噪声）策略，用 stage 1
  观测评估，同样按位姿取向扫一遍。
- **判据**：
  - 定位漂（尤其 stage1 也横放差）→ **模型/表征/奖励问题**（含「横放差 = 单视角
    点云几何退化」这个备选），与遮挡、YOLO、外参全无关。搁置遮挡方向，回去修表征
    （M_OBJ、网络、奖励）。阶梯终止。
  - 定位准 → 坐实是感知链路问题，继续第 3 步。
- **理由**：GT 全表面点云是信息上限；上限都不行，谈遮挡没有意义。

### 第 3 步（仿真内分支）哪类感知绑定

用 GT 掩码做两个互不污染的探针，主口径 = 冻结 baseline 策略 + 换观测：

- **探针 C（纯第一类）**：观测源 = GT + halfspace，`--occlusion_severity` =
  severity_real（±0.1 再取一个点）。
- **探针 D（纯第二类）**：观测源 = GT + 膨胀，N = N_px（p95 再取一个点）。

**判据表**：

| 结果 | 结论 | 去向 |
|---|---|---|
| C 掉、D 不掉 | **第一类绑定** | 链 B 配方 1；遮挡训练（stage 2 occ）是正确杠杆 |
| D 掉、C 不掉 | **第二类绑定** | 链 B 配方 2；杠杆在掩码质量/采点方案（桌面平面过滤一行）|
| 都掉 | 表征对两类都脆 | 表征级改进：M_OBJ 在遮挡下重做消融、第二视角（stage 10）|
| 都不掉 | 感知余量充足 | **别在遮挡上花时间**，去查掩码源 gap 与第 5 步 |

**可行性补充（此时才看训练）**：对绑定的那类扰动跑**一次**训练，看训练曲线能否
收敛到 baseline 水平（及最终评估是否追平）：

- 能 → RL 可吸收，走链 B 的 RL 训练路线；
- 不能 → 走预处理路线（如第二类绑定 → FPS 前加「z 低于桌面 +2cm 丢弃」过滤）。

> 训练曲线只在这一步用于「RL 能不能吸收」的可行性判断，**不用于定位**——定位
> 全部由评估对照完成。

### 第 4 步（仿真内分支）对症训练

按决策表（§6）在 stage4 baseline 上叠加绑定的那类扰动，热启动，不盲加。

### 第 5 步（仿真↔真机分支）gap 排查

- **前提**：此时两边掩码已对齐（stage4 vs 真机都用 YOLO），gap 才可解释。
- **顺序**（便宜到贵、可测到难测）：相机外参 → 深度噪声 → 轨迹跟随 → TCP/基座
  原点/关节零点。
- **自遮挡对齐判据**：同一个夹爪位姿下，比仿真与真机的**工件可见点比例**
  （仿真已记 `env.extras["visible_ratio"]`，真机用 `real_roi_pointcloud.py` 算）：
  - 一致 → 自遮挡对齐，这条排除；
  - 真机明显更低 → 真机夹爪挡得更多，差值即「错配的自遮挡」，回头对齐外参/轨迹。
- **轨迹跟随**：真机实际关节运动跟不上策略指令（伺服滞后/平滑/微超调），是自遮挡
  与观测不一致的第二来源，用 CSV 的 `raw_action vs cmd_delta` 和 `--step_mode` 查。

### 第 6 步（两条路收尾）真机闭环

- **操作**：`--dry_run` 核观测数值 → `--step_mode` 步进核对每步 `joint_rel` 与
  `cmd_delta` → 连续运行。
- 判据：dry-run 里夹爪点（青色）投回 RGB 是否落在真机夹爪上；回初始位姿后
  `joint_rel` 是否接近 0；`visible_ratio` 与仿真对齐。

## 6. 决策表：定位结果 → 链 B 部署训练配方

| 定位结果（链 A） | 链 B 训练配方（在 stage4 基线上） | 说明 |
|---|---|---|
| 第一类绑定 | **stage4（YOLO）+ 几何遮挡**（T3 工具）| YOLO 自带的第二类照单全收（真机本来就有），再叠上可控的第一类 |
| 第二类绑定 | stage4 **本身**，或 +额外膨胀 | YOLO 掩码天然自带第二类；对症训练 = 让 RL 吃真掩码。不够胖再叠膨胀；可先试预处理（桌面平面过滤）|
| 都不敏感 | stage4 即可，**不加遮挡** | 遮挡实验到此为止；部署问题在别的 gap（外参/TCP/深度/轨迹）|
| 解释不了的第三类 | stage4 是唯一解 | 误检夹爪/漏检半块只能实测吸收，合成不了 |
| 第 2 步就漂 | 不做感知，修表征/奖励 | 链 B 暂停 |

**训练细节**：

- 网络结构 217 维不变，可从 stage 2 baseline checkpoint 热启动（`--checkpoint
  <path> --resume`）再微调，省算力。
- YOLO 开销几乎不随 batch 摊薄（~4ms/env），用 **8~16 env 小 batch**；优先
  **stage 4**（`yolo_step=5`，均摊开销 1/5，且与真机「50Hz 控制 + 10Hz YOLO」
  部署节奏一致）。
- 链 B 的遮挡 severity 单独按真机工作点标定（§4.3 的量），**不沿用链 A 的取值、
  不跨链对齐**。

## 7. 真机验证

1. `python scripts/deploy/deploy_pointcloud_policy_xarm7.py --ckpt <链B权重>
   --dry_run`：核观测数值（点云 192 维、可见像素数、掩码面积）。
2. `--mask_source yolo --step_mode`：步进上机，逐步核对动作方向与幅度；
   CSV 记录 `joint_rel / raw_action / cmd_delta`（后两者直接反映轨迹跟随误差）。
3. 连续运行：统计成功率与最终定位误差，与链 A 各探针的评估成绩对照——
   真机成绩应落在链 B 训练分布的预期区间内；若明显更低，按第 5/6 步重新归因。
4. 录像（默认开启）留存纯 RGB，可回灌 YOLO / 重新标注复盘。

## 8. 方法论红线（易错点，违反任何一条定位失效）

1. **先训 stage4 基线，再谈 gap**。仿真↔真机对照必须掩码对齐（两边都用 YOLO），
   否则 gap 被掩码源污染、无法解释。
2. **训练曲线不做定位**。定位全部用评估对照（冻结策略 + 换观测源）；训练曲线只在
   第 3 步可行性判断时出现，回答「RL 能否吸收」。
3. **每级只变一个因素**。换观测源时位姿集、seed、指标、episode 数全部固定。
4. **两个评估口径不混用**（冻结策略换观测 vs 各自训练各自评估），每次对比只选一个。
5. **severity 不跨链对齐**。链 A 的 severity 用于探针，链 B 的按真机当量单独标定；
   stage2+occ 与 stage4+occ 的「同一比例」不是同一观测，也**不需要是**。
6. **不假设 stage2→stage4 的鲁棒性迁移**。链 B 的部署权重直接在 stage4+扰动上训练
   （可热启动，但最终权重由链 B 自己训出）。
7. **不盲加扰动让 RL 探索**。先定位出绑定因素，再把**那一类**扰动喂给 RL。
8. **自遮挡不是独立误差源**，是外参/轨迹的下游结果；「解决夹爪遮挡」= 对齐外参/
   轨迹（`visible_ratio` 对照），不是加遮挡机制。
9. **工作点探测，不画全曲线**。「上限」没有用，有用的是「悬崖 vs 真机工作点」的
   距离——每类在当量附近取 2 个点即可。
